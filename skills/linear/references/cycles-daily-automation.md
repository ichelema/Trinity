# Daily-cycle automation

A pattern (and a script) for treating Linear cycles as **one-cycle-per-day**, with a rolling 14-day forward roadmap, rollover of stale open cycles, and optional auto-assignment of cycle-less work to today's cycle. AWST-aligned by default (`16:00 UTC` boundaries).

The script lives at `scripts/cycles_maintain.py` and is **idempotent** — safe to re-run.

> Pre-read: the cycle-mutation gotchas in [`mutations-cheatsheet.md`](mutations-cheatsheet.md#sub-day-boundaries--gotchas). The +1 ms drift workaround and sequential-update rule are baked into this script; you only need to know they're there if you debug it later.

---

## Concept

Each day gets its own Linear cycle. The intent is to chunk agentic-coding work by session, not by week. A "session" is one calendar day in your working timezone (AWST in this skill — UTC+8, no DST).

| Linear default | This pattern |
|---|---|
| Weekly cycles, auto-generated by `cyclesEnabled` + `cycleDuration` | Daily cycles, manually managed via `cycleCreate` / `cycleUpdate` |
| One active cycle, fixed length | One active cycle = today; 14 future cycles staged ahead |
| Cycle ends → uncompleted issues optionally roll over | Cycle ends → script moves in-progress work to today, closes the old cycle |
| TZ inferred from team config (often UTC) | AWST-aligned (16:00 UTC = AWST midnight); easily switched in code |

## Prerequisites

1. **Disable the team's weekly auto-rollover.** Otherwise Linear keeps spawning week-long cycles in parallel with your daily ones and the roadmap gets messy.

   ```bash
   python scripts/linear.py mutation \
     'mutation($id:String!,$i:TeamUpdateInput!){teamUpdate(id:$id,input:$i){success team{cyclesEnabled cycleDuration}}}' \
     --variables '{"id":"<team-uuid>","i":{"cyclesEnabled":false}}'
   ```

   You can keep `cyclesEnabled: true` and accept the noise, but it's not recommended.

2. **`LINEAR_API_KEY` set in `.env`.** Personal key (`lin_api_…`) or an OAuth `actor=app` token both work.

3. **A scheduler** to run the script daily. Local cron / launchd / systemd timer / GitHub Actions schedule / a hosted worker — anything that fires once a day after AWST midnight (= 16:00 UTC) is fine.

---

## What the script does, in order

```
ensure_roadmap()      → today + N future daily cycles exist
rollover_open()       → stale open cycles: move in-progress issues to today, close them
auto_assign_planned() → (optional) cycle-less issues with eligible state.type → today
```

All three steps query state first, mutate only what's missing/stale. Re-running on the same day is a no-op apart from a few read queries.

### Step 1 — Roadmap (today + 14 days ahead)

For each of `[today, today+1, …, today+14]`:
- Compute the AWST midnight UTC for that day.
- If a cycle already starts within 5 minutes of that target, reuse it.
- Otherwise `cycleCreate` with `name = "Day YYYY-MM-DD"` (AWST date).

The `startsAt` of new cycles is offset by **+1 ms per day in the chain** to satisfy Linear's strict-24h-after rule (see cheatsheet). Drift is invisible in the UI.

### Step 2 — Rollover

For every cycle on the team where `endsAt < now`, `completedAt IS NULL`, and `id != today.id`:
1. Query issues with `state.type ∈ --carry` (default: `started`).
2. `issueUpdate(id, { cycleId: <today> })` for each. Sequential.
3. `cycleUpdate(<old>, { completedAt: <now> })`.

This is the two-step pattern from the cheatsheet, run for every stale open cycle.

### Step 3 — Auto-assign (optional, `--auto-assign`)

Query issues where `cycle.null = true` and `state.type ∈ --assign-states` (default: `started,unstarted`). Assign each to today's cycle.

This catches "planned but not yet slotted" work. Skip the flag if you'd rather leave cycle assignment manual.

## CLI

```bash
# Daily cron — most setups.
python scripts/cycles_maintain.py --team AGI

# 7-day window instead of 14.
python scripts/cycles_maintain.py --team AGI --days-ahead 7

# Also include todos (unstarted) in the rollover sweep.
python scripts/cycles_maintain.py --team AGI --carry started,unstarted

# Plus auto-pull cycle-less planned work into today.
python scripts/cycles_maintain.py --team AGI --auto-assign

# Inspect without mutating.
python scripts/cycles_maintain.py --team AGI --dry-run

# Pin "now" for replay / testing.
python scripts/cycles_maintain.py --team AGI --now 2026-05-09T16:30:00.000Z --dry-run
```

Outputs a one-paragraph summary on stdout: today's cycle id and window, count of created/rolled-over/auto-assigned items, and the team's `cyclesEnabled` flag (a reminder if you forgot the disable step).

## Scheduling

Pick the simplest mechanism that runs once per AWST day, after midnight. Recommended: shortly after 16:00 UTC.

### macOS launchd

A ready-to-edit template ships at `scripts/cycles_maintain.plist.example`. Copy it to `~/Library/LaunchAgents/app.linear.cycles_maintain.plist`, edit the path inside `ProgramArguments`, then:

```bash
launchctl load -w ~/Library/LaunchAgents/app.linear.cycles_maintain.plist
launchctl list | grep cycles_maintain
tail -f /tmp/cycles_maintain.log
```

`Hour`/`Minute` in `StartCalendarInterval` are in the **system's local timezone**, not UTC. The template uses `Hour=16` which assumes a UTC host. Adjust if your host is on AWST (`Hour=0`), AEST (`Hour=2`), or another zone.

### Cron

```cron
5 16 * * * cd /path/to/linear && python scripts/cycles_maintain.py --team AGI >> /tmp/cycles_maintain.log 2>&1
```

### GitHub Actions

```yaml
on:
  schedule:
    - cron: '5 16 * * *'
jobs:
  maintain:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.13'
      - run: pip install httpx python-dotenv
      - run: python scripts/cycles_maintain.py --team AGI
        env:
          LINEAR_API_KEY: ${{ secrets.LINEAR_API_KEY }}
```

## Switching timezones

The script hardcodes AWST (`UTC+8`). To change, edit one line in `scripts/cycles_maintain.py`:

```python
AWST = timezone(timedelta(hours=8))   # ← change this
```

For zones with DST (Sydney AEST/AEDT, US/EU): you'll need a `zoneinfo.ZoneInfo` instead of a fixed offset, and the AWST-midnight helper becomes "local-midnight" in that zone. The +1 ms drift logic stays the same.

## Limitations

- **Drift accumulates.** Each new daily cycle's `startsAt` is +1 ms past the previous. After a year of contiguous daily cycles, that's ~365 ms — still imperceptible, but the chain can't run forever. Reset by archiving older completed cycles (Linear treats archived cycles as out of the chain for validator purposes — verify on your team before relying on it).
- **No `cycleUnarchive`.** If you accidentally archive a cycle, you can't restore it via the API. The script never archives — only closes (`completedAt`).
- **Single-team.** `--team` accepts one key per run. To handle several teams, schedule the script once per team.
- **Auto-assign matches all unscheduled issues with eligible states.** If you have a backlog full of `unstarted` issues you don't want pulled forward, drop `unstarted` from `--assign-states`, or don't pass `--auto-assign`.
- **Webhooks aren't used.** Auto-assign is poll-based at the maintain cadence (e.g. once daily). For real-time auto-assignment on issue-create, subscribe a webhook (`webhookCreate` with `resourceTypes: ["Issue"]`) and call `move_issue_to_cycle` from the receiver. The receiver script lives outside this skill.

## Bootstrapping a fresh team

To start the daily-cycle pattern on a team that's been on the default weekly cadence:

1. Disable the auto-engine (prerequisites step 1).
2. Run `cycles_maintain.py --team <key> --dry-run` to preview the proposed roadmap.
3. Run without `--dry-run` to populate today + 14.
4. Optionally close the team's pre-existing weekly cycles via `cycleUpdate(completedAt: …)` so the daily roadmap is the only active one. (Don't archive them — `cycleArchive` is one-way.)
5. Schedule the script.

That's the full setup.
